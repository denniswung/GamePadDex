# GamePadDex 设计结构（v1.42）

## 一、设计目标与约束

| 目标 | 设计手段 |
|---|---|
| 手柄完全脱离三星原生控制 | 由 root 助手 `EVIOCGRAB` 独占，框架层收不到原始事件 |
| 任意 App 里都能当鼠标/键盘/触摸 | 三种注入通道：uinput 鼠标、uinput 键盘、`input` 触摸/按键 |
| 映射可配置、可组合、可扩展 | **Action 词汇表 + 槽位配置 + 路由表**三层分离 |
| 跨进程稳定 | 单实例锁 + 行协议 + 心跳 + 两级看门狗 |
| 不依赖 DeX（v1.42） | 显示抽象收敛为「当前亮着的内置屏」 |
| 可回归验证 | 链路门禁 + 25 项自动化 + 坐标探针 |

## 二、总体分层

```
┌──────────────────────────────────────────────┐
│ L0 表现层  ConfigActivity / ButtonDetail      │  读写 Prefs，展示 EngineState
├──────────────────────────────────────────────┤
│ L1 引擎层  EngineService（8ms 循环）          │  输入状态机：指针/摇杆/组合/双击/手势
├──────────────────────────────────────────────┤
│ L2 决策层  ActionRouter + Actions + Prefs     │  「按键 → 动作」纯决策，不碰 IPC 细节
├──────────────────────────────────────────────┤
│ L3 链路层  RootInput（socket 客户端）         │  连接/心跳/重连/行编解码
├──────────────────────────────────────────────┤
│ L4 执行层  gpminput（root 原生）              │  独占设备、uinput、注入、电源/旋转/切应用
├──────────────────────────────────────────────┤
│ L5 系统    Linux input / uinput / Android     │
└──────────────────────────────────────────────┘
```

**设计原则**
- **分层单向依赖**：上层只调下层接口；引擎不知道 socket 细节，路由不知道 OS 细节。
- **决策与执行分离**：`ActionRouter` 只产出「要做什么」，`RootInput` 负责「怎么发」。
- **状态集中**：可变的输入状态（按住的键、摇杆、模式、箭头导航）只在 `EngineService` 内，避免跨层共享。
- **默认值不可变**：`Prefs` 的默认值是冻结常量，用户覆盖只写 SharedPreferences。

## 三、核心抽象

### 1. Action（动作词汇表）

```
Action = { id: String, label: String }
```

- **无参数 id**（`left_click`/`center_cursor`/`power`…）
- 带参数的动作（`key_combo`、`tap`、`swipe`）参数存在**槽位值**里，而不是动作对象里 → 同一动作可在多处复用不同参数。
- 三类执行语义：**瞬时**（点击/按键）、**按住型**（滚轮/缩放/滑动滚动）、**状态型**（切换鼠标模式、电源）。

### 2. Binding（按键绑定模型）

```
Button ──┬─ 单击 action
         ├─ 双击 action
         ├─ 组合 slot（首位键 + 次位键 → action）
         └─ 长按（预留）
```

**组合键槽位设计**
- 24 个固定槽位（`mix_<i>_keys` / `_action` / `_value`），键集合用 `+` 连接。
- 槽位是**声明式**的：引擎启动时编译成 `Map<KeySet, Slot>`，运行时只查表。
- 首位键（X/Y）触发「组合裁决窗口」：按下时挂起自己的单击动作 220ms，命中组合则取消单击。
- 冲突规则：先按下的组合获胜；同一键不能既作首位又作次位。

### 3. DisplayState（显示抽象）

- v1.42 后只有一种语义：**当前亮着的内置屏**（Fold 内屏或外屏）。
- `active()` / `size()` / `rotation()` 是引擎唯一的显示信息入口 → 未来若要加别的显示，只改这一处。

### 4. RootInput（链路抽象）

- 接口是**命令式**的（`move`/`swipeV`/`pointKey`/`powerKey`/`setRotation`…），不是裸 socket。
- 内部维护：连接状态、心跳时间、最后一行时间、重连节流。
- **设计约束**：所有命令幂等或可重发；断链时引擎只做「释放按住状态」，不重放历史。

## 四、输入处理设计

### 1. 引擎循环（8ms）

```
tick:
  1. 读摇杆向量 → 死区/曲线 → 指针增量（或滚动/滑动）
  2. 处理按住型动作的重复发射（滚轮、缩放、滑动滚动）
  3. 超时检查：组合裁决、双击窗口、箭头导航锁定
  4. 每 250 tick 校准一次期望模式（防外部改动）
```

**指针管线**：`原始轴值 → 死区(16%) → 归一化 → 曲线(指数 1.6) → 速度(px/帧) → 累积余数 → REL 事件`
- 累积余数保证慢推不丢步；精度模式（X+摇杆）把速度乘 15%。

**滚动管线**：`右摇杆 → 滚动死区(35%) → 曲线 → 方向选择 → 触摸长拖 / wheel 事件`
- 触摸拖动是「手势线程」：一次手势 450ms，间隔 40ms 连续排程，保证内容不停。
- 信息流类 App 切到「一条一次」策略（按 `topPkg` 选择 profile）。

### 2. 手势状态机（每 App 一个 profile）

| profile | 触发 | 手势 |
|---|---|---|
| 通用 | 普通 App 上滑 | 35% 屏高 / 450ms，连续排程 |
| 信息流 | 抖音/红果/PiliPlus | 30% / 150ms，一条一次 |
| 桌面 | HOME 上报的启动器 | 底部起手 88%/12%，45%，一次一格 |
| 下拉 | 任何非信息流 | 顶边 3% 起手，45%，一次 |
| 缓慢 | 绑定「缓慢滑动」 | 25% 屏高 / 120ms |

**设计要点**：profile 不是硬编码 if，而是「策略选择函数」——输入是 `topPkg` 与方向，输出是 `(起手点, 距离, 时长, 冷却)` 四元组。

### 3. 方向键双模

- **原生导航**（默认）：手柄 D-pad 以 `PAD` 转发给系统，焦点移动由 Android 处理；A 在导航态发 `DPAD_CENTER` 而不是点击光标处。
- **光标模式**：摇杆一动即退出原生导航（带 300ms 锁定），恢复指针。
- 设计理由：纯触摸 App 没有焦点，纯按键 App 又不需要光标 → 用「谁先动」决定模态。

## 五、通信协议设计

```
App → Helper（单字母命令 + 空格参数）
  B <idx> <0|1>     按键
  A <axis> <val>    轴
  M <x> <y>         相对移动
  W <disp> <dy> <ms> <w> <h> [pct]   竖向滑动
  S <disp> <dx> <ms> <w> <h>         横向滑动
  K <disp> <code>... 组合键
  P <disp> <code>    点按
  p                  电源键
  r <1|0|-1>         旋转
  L                  关闭前台应用
  O <w> <h> [park]   居中
```

**设计约束**
- **无请求 ID**：命令都是单向，执行结果用事件行异步回传（`SWIPE rc=0`、`CENTER`）。
- **心跳双向**：助手每 2s `PING`，App 每行更新 `lastLineAt`；6s 静默判定断链。
- **单实例**：`flock(helper.lock)` + 连接探测 → 保证「谁抢到设备谁服务」。

## 六、生命周期与恢复设计

```
App 启动 ─▶ ensureRunning ─▶ 连接 socket ─▶ 发 READY 握手
                                     │
                          失败 → 6s 后重试（指数退避）
                                     │
        ┌────────────────────────────┴──────────────┐
        │ 助手崩溃：KSU service.sh 每 2s 检查 pid     │
        │ App 崩溃：助手检测 EPIPE 退出，等待重连      │
        └───────────────────────────────────────────┘
```

**两级看门狗**：KSU 守护进程（root）管助手；助手管「App 是否还活着」。任一侧崩溃另一侧都能自愈，不残留 grabbed 设备。

**模式持久化**：`mode_on` 写盘 → 服务重启不改变用户选择；断链时引擎本地置 off 并释放按键，但**不写盘**（重连后恢复）。

## 七、配置模型

```
SharedPreferences（唯一真相）
  ├─ 全局：enabled, mode_on, force_landscape, wheel_speed, ...
  ├─ 指针：speed_phone, deadzone, precision
  ├─ 滚动：scroll_speed, scroll_deadzone, v_touch_scroll, invert_scroll
  ├─ 键位：btn_<key> / combo_<key> / double_<key>
  └─ 组合：mix_<i>_keys / _action / _value（24 槽）
```

- **读放大**：引擎每 8ms 读内存缓存的 Prefs，`Prefs` 变更通过 `OnSharedPreferenceChangeListener` 刷新缓存。
- **默认值**：代码常量（`defaultAction/defaultMixKeys/...`），新装即生效；老用户只覆盖显式改过的键。

## 八、测试设计（可回归）

| 设计元素 | 作用 |
|---|---|
| **前置门禁** `dexpad_precondition.sh` | 断链时直接 abort，避免「假失败」污染结果 |
| **坐标探针** `PointerProbeActivity` | 唯一可信的指针位置来源（hover 坐标是窗口局部坐标，不可用） |
| **25 项清单** | 按「链路→指针→导航→滚动手势→居中→应用切换→模式→崩溃恢复→抽屉/通知栏→横屏→电源」分区 |
| **断言方式** | 优先用日志事件（`SWIPE`、`POWER`、`CENTER`）、窗口计数、状态字段；截图字节数仅作辅助 |
| **夹具** | `vgpad` 手柄注入、`gpmcmd` 直连助手、`dexpad_restart_clean.sh` 复位环境 |

## 九、扩展点（设计上预留）

| 想加什么 | 改哪里 |
|---|---|
| 新动作 | `Actions.kt` 加 id/label → `ActionRouter` 加分支 → `ButtonDetailActivity` 自动出现在列表 |
| 新按键 | `Prefs.BUTTONS` + `KeyCodes.kt` 码表 |
| 新 App 手势 profile | `EngineService` 的策略函数加一条 `topPkg` 规则 |
| 新平台（如平板/外接屏） | 只实现 `DisplayState` 与 `RootInput` 的显示/注入接口 |
| 新注入方式（如无障碍） | 在 L4 增加一条执行通道，L1–L3 不动 |

## 十、已知设计取舍

1. **uinput 优先而非无障碍**：原生、无延迟、不被 App 检测；代价是必须 root。
2. **触摸滑动用 root `input` 注入**：跨 App 通用；代价是手势只能「一次一段」，靠连续排程模拟长滑。
3. **指针居中无反馈**：Android 16 拿不到全局光标坐标，只能靠「夹角落 + 增益模型」开环定位；增益随系统加速度变化，所以标定值写死为 2.16 并在清单里用探针守护。
4. **组合键 220ms 裁决**：换来无冲突，代价是首位键单击有轻微延迟；Y+L3 电源键因此也是「按住 Y 再按 L3」。
5. **单实例助手**：避免多实例抢设备，代价是 App 必须依赖 KSU 守护或手动启动。
