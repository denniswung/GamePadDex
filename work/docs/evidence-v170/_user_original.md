# GamePadDex 详细测试用例（滚动 / 手势 / 混合界面专项）

> **建议保存到仓库：** `docs/TEST-CASES-v1.69.md`  
> **测试基线：** 当前仓库 `main` 分支 README 标注的 v1.68（`com.dennis.dexpad` versionCode 70）及现有 `padtest` 测试台。  
> **文档用途：** v1.68 已有自动化用例的扩展测试计划，重点补足复杂滑动、嵌套滚动、双栏/浮层混合界面、输入控件与滚动手势冲突。本文中的新增验收要求是建议的测试标准，不代表这些项目已经在真机通过。

---

## 1. 测试目标与范围

GamePadDex 不只是一个普通设置 App。它包含手柄输入独占、root helper、uinput 注入、LSPosed 设置入口、映射配置页，以及独立的 `padtest` 事件测试台。因此必须分别验证：

1. **输入链路：** 手柄 → `gpminput` / evdev → Unix socket → `EngineService` → uinput → Android 输入分发 → 前台控件。
2. **动作行为：** 光标移动、LB/RB 连续拖拽或滚轮、右摇杆滚动、按键/组合键、模式切换。
3. **界面行为：** 外层 `ScrollView`、内部 `ListView`、`HorizontalScrollView`、自绘双轴视图、左右独立列表、固定区域、浮动日志/报告入口之间的触摸归属与滚动隔离。
4. **设置行为：** 竖屏单列、横屏双列、SeekBar、Switch、映射列表、按键详情、选择器和 AlertDialog。
5. **稳定性：** 长时间输入、快速反向、页面切换、前后台、旋转、DeX、多窗口、断连重连、报告导出。

### 1.1 本次依据的实际界面结构

| 页面 / 类 | 当前源码中的实际结构 | 本文重点验证 |
|---|---|---|
| `ScrollTestActivity` | 外层 `ScrollView`；纵向 200 项 `ListView`；5 页 `HorizontalScrollView`；`AxisLockView`；左右两个独立 `ScrollView`（各 40 行）；固定区域 | 外层/内层滚动归属、横纵手势仲裁、列表焦点锚定、固定区回退 |
| `ProbeActivity` | 页面内容放在 `FrameLayout`；右上角常驻「日志」「报告」浮层入口；统一分发按键、鼠标、触摸事件 | 浮层命中、边缘滚动、底层内容误触、页面切换 |
| `LogActivity` | 两行筛选/操作按钮、事件数量、占满剩余空间的 `ListView`；最多展示最近 400 条 | 高频日志、筛选、暂停、清空、列表自动跟随与手动滚动冲突 |
| `ReportActivity` | 外层滚动页面；开始/结束、TXT/JSON 导出、清零、摘要卡片和详细结果 | 结果长页面、滚动与按钮交互、会话边界及导出 |
| `ConfigActivity` | 竖屏单个 `ScrollView`；宽屏左右两个独立 `ScrollView`；左侧设置/状态/指针/滚动，右侧映射/数据 | 双栏独立滚动、SeekBar/Switch 拖动、映射行与长按菜单、导入导出 |
| `ButtonDetailActivity` | 竖屏单列；宽屏左侧单击/双击/长按，右侧组合键；动作选择器、应用选择器、包名输入框、多选组合键对话框 | 双栏独立滚动、对话框列表滚动、长按/单击竞争、输入法遮挡 |

### 1.2 优先级定义

- **P0：** 核心输入/滚动错误、错误页面/列表接收事件、松手不停、模式混用、数据丢失、崩溃/ANR。发布阻断。
- **P1：** 主要功能退化、边界场景错误、双栏/混合界面操作异常、导出结果不正确。建议发布前修复。
- **P2：** 视觉、低频设备兼容性、极端压力下的体验问题。记录并排期。

### 1.3 测试结果填写模板

每条用例执行后填写：`PASS / FAIL / BLOCKED / NOT RUN`，记录设备、系统、屏幕方向/分辨率、连接方式、应用/模块/helper 哈希、参数、复现次数、日志/截图路径。**不得只写“看起来正常”**；滚动用例至少记录开始/结束位置或偏移量，关键 LB/RB 用例还要记录 helper 事件计数和拖拽总位移。

## 2. 测试环境与准备

### 2.1 标准环境

| 项目 | 标准配置 / 要求 |
|---|---|
| 目标设备 | Samsung Galaxy Z Fold4（SM-F9360），Android 16；至少覆盖折叠内屏和外屏 |
| 权限与框架 | KernelSU Root；LSPosed 或 Vector 已启用，作用域包含 `com.android.settings` |
| 被测组件 | `com.dennis.dexpad`、`gpm_dex` 模块、`gpminput` helper 三者版本一致 |
| 手柄 | Xbox / 标准 XInput 手柄；至少一种 USB 连接和一种蓝牙连接 |
| 测试台 | `com.dennis.padtest` 已安装；测试时记录实际 APK 版本和构建类型 |
| 模式 | 鼠标模式开启；另安排鼠标模式关闭的系统原生交还测试 |
| 屏幕 | 亮屏解锁；标准基线先固定横屏，再测竖屏/折叠状态/DeX |
| 网络 | 核心手柄测试不依赖网络；「打开应用」测试所需 App 预先安装 |

### 2.2 每轮测试前检查

1. 记录 `dumpsys package com.dennis.dexpad` 的 `versionName/versionCode`。
2. 对照发布包 SHA256，确认设备 APK、模块内 helper、发布 helper 字节一致；禁止拿 debug helper 结果冒充 release 验收。
3. 检查 helper 单实例、Unix socket 存在、EngineService 正常、心跳就绪；记录 `logcat` 和 helper 日志起始位置。
4. 确认手柄被识别；鼠标模式开启后系统不再收到原始手柄方向键/焦点事件，映射后的鼠标/键盘事件正常。
5. 清空上一轮 `padtest` 日志与报告，开启新的报告 session；不要在上一轮残留滚动位置上直接判定。
6. 记录屏幕逻辑尺寸、rotation、密度、折叠状态、DeX display/task 信息；同一组对比用例期间不要偷偷改变分辨率。

### 2.3 推荐证据源

| 证据 | 主要用途 | 注意事项 |
|---|---|---|
| `padtest` 报告 JSON | 页面自检、可检测的 PASS/FAIL/UNKNOWN | UNKNOWN 不能计为 PASS |
| `logcat -s PadProbe` | 测试 App 真正收到的按键/鼠标/滚轮/触摸事件 | 收到事件不代表目标控件确实滚动 |
| `logcat -s DexPad` / helper log | 映射决策、drag start/end、SWIPE/WHEEL 计数、异常和断连 | 区分应用侧和 helper 侧的计数 |
| `adb shell dumpsys input` / `dumpsys window` / `dumpsys activity` | 输入设备、前台窗口、Display/Task 状态 | 截取测试前后快照，避免只凭单次输出 |
| `uiautomator dump` | 当前控件树、可见列表项、焦点/页面状态 | 高频刷新页面可能导致 dump 不稳定 |
| `screencap` | 比较实际内容位移、页面错位、遮挡和误触 | 同一分辨率、同一裁切区域、同一时间点对比 |
| `getevent`（必要时） | 验证 uinput 触摸帧、边界续拖、抬手 | 用于核对真实 down/move/up，而非只数日志行 |

**重要：** `adb shell input swipe` 是直接向 Android 注入触摸，不能替代真实手柄通过 `EVIOCGRAB → gpminput → uinput` 的端到端测试。它只能用于单独检查控件本身，不得作为 GamePadDex 映射链路通过的依据。自动化驱动优先复用仓库现有 `vgpad` / `work/scripts`，真机手柄再做抽样复验。

### 2.4 基线数值（v1.68 已有定义）

以下是现有 v1.68 用例中的可复用标准，不要与新增建议阈值混淆：

| 场景 | 现有基线 / 通过口径 |
|---|---|
| LB/RB 触摸拖拽 100 ms | 总位移大于 0 且不超过 150 px |
| LB/RB 触摸拖拽 300 ms | 大于 100 px 且不超过 450 px；相对 100 ms 单调增加 |
| LB/RB 触摸拖拽 1.5 s | 总位移 1200–2200 px（默认 `scroll_speed=4`，约 1.0×） |
| 触摸拖拽事件类型 | 拖拽期间 `SWIPE=0` 且 `WHEEL=0`，一次按压是一组 down→move→up |
| 滚轮模式 1.5 s | `WHEEL≥6`、`SWIPE=0`；现有实测为 9 次 WHEEL |
| 松手后 | 不应继续生成拖拽 move；现有复验使用 500 ms 观察窗，额外位移容差 ≤200 px |
| 边界续拖 | 距 task 边缘约 80 px 时 up + 新锚点 down，内容偏移应连续；最终累计上限约 2200 px × 倍率，容差按现有文档约 ±1% |
| 滚动速度参数 | `scroll_speed` 1–10 映射倍率 0.6×–1.8×；按压开始时快照，按压中修改不改变当前按压倍率 |
| 隐藏光标后的滚轮 | 按压开始将指针移到 task 中心建立滚轮锚点；仍受目标窗口悬停区域限制 |

## 3. 滚动与滑动专项用例

### 3.1 LB/RB 连续拖拽与滚轮后端

| ID | 优先级 | 操作步骤 | 预期结果 / 证据 |
|---|---|---|---|
| SCR-001 | P0 | 开启「上下滑动用触摸拖动」；将目标 App 放在列表顶部；RB 按住 100 ms 后松开，连续执行 3 次 | 每次只产生一组 down→move→up；位移 0–150 px 且大于 0；不能一次跳过整屏；三次均能重新开始 |
| SCR-002 | P0 | 同一位置 RB 按住 300 ms；记录引擎 `drag end total` | 位移 100–450 px，并大于 100 ms 位移；不得出现 300 ms 内突然跳页 |
| SCR-003 | P0 | RB 按住 1.5 s；记录总位移、帧数、helper SWIPE/WHEEL 计数及前后内容截图 | 位移 1200–2200 px；SWIPE=0、WHEEL=0；画面逐段推进，无离散大跳 |
| SCR-004 | P0 | 对 LB 重复 SCR-001～003 | 与 RB 使用相同连续拖拽机制；方向相反；不能只有 RB 生效 |
| SCR-005 | P0 | 对同一列表分别执行 LB 和 RB，检查内容首尾标记 | LB/RB 的内容移动方向符合当前键位定义；不得反向、方向不一致或因显示旋转产生轴交换 |
| SCR-006 | P0 | RB 按住 1.5 s 后突然松开；在松手后 500 ms 内不再触碰手柄 | `up` 被发出；无额外 move；内容不得继续滑动；累计额外位移 ≤200 px（按现有 v1.68 口径） |
| SCR-007 | P1 | 100 ms、300 ms、500 ms、800 ms、1.1 s、1.5 s 分别执行 RB，每次回到相同起始位置 | 位移总体单调；相邻阶段不出现反向或明显突然跳变；保留每段引擎日志 |
| SCR-008 | P1 | 单次 1.5 s 拖拽中，分别在 400 ms 前、400–1400 ms、1400 ms 后松手 | 速度爬升符合当前实现：初段较慢、中段线性升速、后段封顶；不同阶段无突然反向或丢帧 |
| SCR-009 | P0 | `scroll_speed` 依次设为 1、2、4、7、10；每档从同一列表位置按住 RB 1.5 s | 位移随档位单调增加；默认 4 为约 1.0×；档位 1/10 不应超出当前倍率定义；记录每档倍率和位移 |
| SCR-010 | P0 | RB 按住约 1.7 s，在按压中把 `scroll_speed` 从 4 改为 10，继续按到 2.5 s 再松手 | 本次按压仍使用起手时快照的 1.0×；下一次按压才使用 10 档；不能在中途突然提速 |
| SCR-011 | P0 | 开启触摸拖动，连续按 RB 1.5 s，再按 LB 1.5 s | 每次按压互相独立；无残留 pointer-down；每次松手之后下一次动作能正常开始 |
| SCR-012 | P0 | 触摸拖动打开时按住 RB；在按压期间关闭开关；继续保持 1 s 后松手 | 本次按压不能从触摸拖动切换成滚轮；无 SWIPE/WHEEL 混合；下一次按压才使用关闭后的滚轮模式 |
| SCR-013 | P0 | 触摸拖动关闭时按住 RB；在按压期间打开开关；继续保持 1 s 后松手 | 本次按压仍只产生滚轮；下次按压才使用触摸拖动；不能重复或丢失释放事件 |
| SCR-014 | P0 | 关闭触摸拖动；RB 按住 1.5 s | 纯滚轮模式；WHEEL≥6 且 SWIPE=0；现有测试基线可对照约 9 次 WHEEL |
| SCR-015 | P0 | 关闭触摸拖动；LB 按住 1.5 s | 与 RB 一样走纯滚轮；方向符合键位定义；WHEEL≥6、SWIPE=0 |
| SCR-016 | P1 | 先让指针空闲隐藏，再按 RB 触发滚轮模式 | 滚轮开始前自动建立可用锚点；不会因为没有可见指针而完全无效；记录指针重建耗时和第一轮 WHEEL |
| SCR-017 | P1 | 滚轮模式下把指针分别放在可滚列表、视频区域、不可滚空白区域，再按 RB | 只在目标窗口当前悬停位置有效；不可滚区不应误滚其他窗口；如无效应能由日志定位为悬停限制，而不是误报为 helper 断链 |
| SCR-018 | P1 | 在可滚列表按住 RB，随后切到另一个 App；保持按压并松手 | 旧窗口不再持续接收滚动；切换前后不存在残留按压；新窗口下一次按压可正常工作 |
| SCR-019 | P1 | 在多窗口模式下切换前台 task，立即按 RB，再间隔 2.5 s 重复 | task 边界缓存不应导致长期滚错窗口；允许记录当前实现最多约 2 s 的边界缓存窗口，缓存更新后必须定位正确 |
| SCR-020 | P1 | 在 task 顶部、底部附近分别长按 RB/LB，覆盖到达边界和离开边界 | 不越过可滚区域；边缘续拖时内容位置连续；不把新锚点落到通知栏、导航栏或相邻窗口 |

### 3.2 右摇杆、轴向仲裁与普通滚动

| ID | 优先级 | 操作步骤 | 预期结果 / 证据 |
|---|---|---|---|
| SCR-021 | P0 | 在测试台 200 项纵向列表中，右摇杆向上保持 2 s，再向下保持 2 s | 列表先后向两个方向移动；`offset` / 首可见项变化；松手后持续状态在约 400 ms 后归零 |
| SCR-022 | P0 | 在 5 页横向区，右摇杆向左、向右分别保持 2 s | `scrollX` 和近似页码变化；只横向滚动，不使外层页面垂直乱跳 |
| SCR-023 | P0 | 右摇杆同时斜推（上+左、上+右、下+左、下+右）各 2 s | 每个 tick 只仲裁一个主轴；不得出现纵横同时滚动或轴向抖动；方向选择稳定 |
| SCR-024 | P1 | 右摇杆仅轻推到死区边缘，再分别缓慢越过阈值 | 死区内不滚；越过阈值后开始滚；回到死区立即停止，不保留上一方向的滤波量 |
| SCR-025 | P0 | 右摇杆持续上推 3 s，松开后立即观察 1 s | 松手即停止；不出现残余滑动、自动反弹或隔一段时间再补发动作 |
| SCR-026 | P1 | 快速执行上→下→上→下，每段约 150–300 ms，连续 20 轮 | 每段方向都正确；无旧方向残留、滚动速度叠加失控、死锁或事件积压 |
| SCR-027 | P1 | 分别设置水平/垂直灵敏度不同的值，进行右摇杆水平和垂直滚动 | X/Y 灵敏度只影响对应轴；修改 X 不改变纵向滚动，修改 Y 不改变横向滚动 |
| SCR-028 | P1 | 打开「反向滚动」，重复 SCR-021；关闭后再次重复 | 开关只反转方向，不改变轴选择、速度档位、松手行为；关闭后恢复默认方向 |
| SCR-029 | P1 | 推右摇杆斜向移动，在同一过程中再按 LB/RB | 右摇杆与肩键动作不串扰；不重复触发两种垂直滚动；日志能够区分输入源和动作源 |

## 11. 当前测试台的观测盲区 / 已知限制（不要误判）

这些项目需要在测试报告中单独标注，不能把测试台测不到直接判为产品通过，也不能把已知测试台限制误判成主应用回归：

1. **ProbeActivity 触摸路径没有逐帧记录 `ACTION_MOVE`。** 当前统一事件记录主要捕获 DOWN/UP，并按起终点距离是否大于 40 px 派生 swipe。因此不能只靠 `PadProbe` 判断 8–16 ms 触摸帧是否连续；连续性要看 helper `getevent`、engine drag frame 和 `drag end total`。
2. **ScrollTest 的手势桥接只是探针辅助。** `ScrollTestActivity` 会把识别到的 swipe 位移桥接到 ListView/HorizontalScrollView，适合验证输入被识别和控件可响应，但它不是第三方真实 App 的原生滚动行为。真实 App 必须另做端到端验证。
3. **固定区域计数需要额外核实。** 当前 `ScrollTestActivity` 中 `fixedAreaScrolled` 有显示逻辑，但在该文件现有代码路径中未见递增点；因此 `fallbackState` 文案不能单独作为固定区回退通过依据。应检查 helper 的焦点锚点/实际列表 offset，或先补充可靠埋点。
4. **左右列表的焦点证据需要检查两侧 offset。** 当前状态文字在某个列表滚动时显示该列表，但“另一列表没有动”必须通过双侧 offset/截图确认，不能只看状态文字。
5. **padtest 页底 LB 锚点已知限制。** 仓库现有 v1.68 文档说明：padtest 页底 LB 锚点可能落到内层 ListView，导致外层页面 offset 不动；真实 App 的两个方向已有单独验证。这个现象应记录为测试台覆盖限制，并用真实 App 补验，不能把它当成真实 App 必然失败。
6. **滚轮受悬停区域限制。** `ensureWheelAnchor` 可以缓解隐藏指针后的无锚点问题，但目标 App 可滚区域不在指针锚点处时仍可能滚不动。此时记录指针位置、窗口 bounds 和目标滚动区域。
7. **DeX 外接显示器覆盖不完整。** 当前仓库说明触摸点击、双指缩放在 DeX 外接屏尚未完整验证；必须作为独立兼容性项目，不要沿用手机屏的 PASS。
8. **多窗口 task 边界缓存约 2 秒。** 切换 App 后短时间内可能使用旧边界；测试应同时记录切换后立即执行与等待 2.5 秒后执行的结果。
9. **触摸点击坐标存在估算误差。** 在目标设备无法读取可靠系统指针坐标的情况下，触摸点击模式不应采用与默认鼠标点击相同的严格坐标精度门槛；应单独记录偏差，默认鼠标事件作为基础回归。
10. **显示尺寸变化会影响坐标空间。** `display_size_forced` 或逻辑分辨率发生变化后必须重新验证边界夹取、居中和触摸映射；不能复用旧标定结果。
