# v1.59 发布说明（2026-11-14）

包名：`com.dennis.dexpad`　versionCode **61** / versionName **1.59**
配套：KernelSU 模块 `gpm_dex` v1.59 · 助手 `gpminput` v1.59

## 修的问题：滑动首帧卡顿（助手同步查 dumpsys）

**原因**：滚动手势（右摇杆上下、LB/RB、X+方向键翻页）最后都会调助手的 `cmd_swipe`，
它里面**每次都同步**跑两条 `dumpsys`：

- `dumpsys activity activities` → 取前台 task 边界（约 100–300 ms）
- `dumpsys input` → 取光标位置（再 100–300 ms）

这两条都在助手的**命令主循环**里同步执行，所以一次滑动的第一帧要等 200–600 ms，
期间手柄事件全被憋住——表现就是"滑动第一下卡一下、按了没立刻动"。

**改法**：

1. **task 边界改成缓存 + 后台刷新**：缓存文件 `/data/adb/gpm/taskbounds.txt`，
   由子进程在后台刷新（最多 2 秒一次）；`cmd_swipe` 只读内存/文件，**绝不同步 dumpsys**。
   缓存还没建立时用全屏边界兜底（绝大多数应用本来就是全屏），不会因此卡住。
2. **光标位置不再 dumpsys**：App 本来就知道光标估算位置，现在随滑动命令一起传给助手
   （命令末尾追加 `cursorX cursorY`），助手直接使用；没有坐标时才回退到上次已知值 / task 中心。
3. 顺手加了 `prep=` 计时日志，滑动准备耗时可以直接在 `helper.log` 里看到。

**实测**（`/data/adb/gpm/helper.log`）：

```
SWIPE 0 1280,1040 -> 1280,560 (task 0..2560 / 0..1600) async prep=1005us
SWIPE 0 1280,1040 -> 1280,560 (task 0..2560 / 0..1600) async prep=382us
SWIPE 0 1280,480  -> 1280,1040 (task 0..2560 / 0..1600) async prep=370us
```

准备耗时从 **200–600 ms 降到 0.4–1.1 ms**。

## 附带

- 光标锚定更准：RB/LB/翻页滑动现在从**光标位置**起手（实测 `1280,800` → `1280,400`）。
- 任务边界缓存同样服务于"滑动必须落在应用内"的逻辑，缓存过期自动后台更新。

## 已知限制

- 应用切换后最多 2 秒内，滑动可能仍按上一个应用的 task 边界计算；因为缓存节流为 2 秒。
  （只有多窗口/分屏等非全屏场景才会感觉到，全屏应用无影响）
- 触摸点击模式仍依赖光标估算，可能点偏（默认用鼠标事件）。
