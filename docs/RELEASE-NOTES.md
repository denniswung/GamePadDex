# v1.64 发布说明（2026-11-14）

包名：`com.dennis.dexpad`　versionCode **66** / versionName **1.64**
配套：KernelSU 模块 `gpm_dex` v1.64 · 助手 `gpminput` v1.64 · 测试台 `com.dennis.padtest` v1.1

## 1. 光标空闲隐藏后，**回到上次的位置**（不再是屏幕中心）

v1.63 为了避免"光标卡边界"，重建鼠标设备后是直接拉回屏幕中心。
按你的要求改成了**回到上次的位置**：

- 助手新增 `P <x> <y> <w> <h>` 绝对定位命令：
  先把光标**有界推到左上角(0,0)**（撞屏幕边缘，所以不管当前在哪都能对齐），
  再按增益一步移动到目标坐标 → 精确绝对定位，不依赖"真实光标在哪"。
- 引擎在光标恢复时（空闲隐藏 / 助手重连）把**上次的估算坐标**发给助手，
  光标就出现在你离开时的位置。
- 恢复后 260ms 内忽略摇杆惯性，避免刚回来就被推走。

实测日志：

```
engine: pointer shown at last position 1875,1600 (2560x1600)
helper: MOUSE_REOPEN (auto) | POINTER on | POSPTR 1875,1600
```

测试台实测落点：离开前 `1664,1143` → 恢复后点击 `1662,1143`（误差 2px）。

## 2. 顺手修掉了「SELECT 通知栏」之前其实是假通过

原来用 uinput 的 `KEY_NOTIFICATION_CENTER(444)`，日志显示 `NOTIF uinput=1`，
但截图对比证明**通知栏根本没展开**（之前的用例阈值太小，属于假通过）。

改成**从顶部边缘下滑的真实触摸手势**（和手指下拉通知栏完全一样）：

```
NOTIF swipe async | NOTIF swipe rc=0
截图 274KB -> 4248KB   ← 通知栏确实展开了
```

测试用例也从"截图差 >200 字节"改成"截图差 >500KB"，避免再假通过。

## 4. 已知限制

- 恢复到"上次位置"依赖增益标定（`centerGain`）；增益不准时会有几十像素误差，
  可在设置里微调「居中增益」。
- 光标空闲隐藏后第一次推摇杆，位置恢复会有约 0.3 秒的准备时间（助手在推光标）。
