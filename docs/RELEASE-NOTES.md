# v1.50 发布说明（2026-11-13）

包名：`com.dennis.dexpad`　versionCode **51** / versionName **1.50**
配套：KernelSU 模块 `gpm_dex` v1.50 · 助手 `gpminput` v1.50

## 本版修复：L3 居中不是"一次到位"

**原来的做法**（会跳、且不准）：

```
cmd_mouse_move(-30000, -30000)   // 先把指针顶到左上角
sleep(90ms)
cmd_mouse_move(tx / 2.16, ty / 2.16)   // 再按固定增益 2.16 猜一次
```

两个问题：① 中间有"回左上角"的可见跳变；② 系统开了指针加速，2.16 这个常数并不稳定，落点会偏。

**现在的做法**：新增一个 **绝对指针设备**（`Gamepad Absolute Pointer`，`EV_ABS` + `ABS_X/ABS_Y`，无 `INPUT_PROP_DIRECT`，系统当鼠标处理）。居中就是**一条绝对坐标事件**：

```
EV_ABS ABS_X = 32767/2
EV_ABS ABS_Y = 32767/2
SYN
```

- 一条事件到位，没有中间态，不跳；
- 50%/50% 与分辨率、旋转、指针加速**都无关**，所以不会偏；
- 相对鼠标仍负责日常移动/点击/滚轮（手感不变）；
- 绝对设备若创建失败，自动退回旧的线性兜底（日志会写明 `CENTER(linear … fallback)`）。

## 验证

```
安装版本           1.50
助手链路            ok
绝对指针设备已创建   ok
连按 3 次居中位置一致  (225.985, 1880.44) ← 三个值完全相同
走绝对指针          abs=3  linear=0
Y -> Home（无电源）  ok
松手不滑行          ok
空闲隐藏指针        1 -> 0
无崩溃              ok
```

> `dumpsys input` 给出的 hover 坐标本身不可靠（会超出屏幕尺寸，早前已记录过这个坑），
> 所以判断依据是：**每次按 L3 只有一条 `CENTER(abs)`、三次落点完全一致、没有线性兜底**。
> 绝对坐标 50% 即屏幕中心，这一点由协议本身保证。

## 已知限制

- 绝对指针设备的坐标范围固定 0..32767，量化误差 <1 px。
- 隐藏指针（销毁设备）与居中恢复之间约有 100 ms 的设备重建；连续快速操作时不会丢事件，但会多一次重建。
